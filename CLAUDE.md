# CLAUDE.md — BYOP (Bring Your Own Podcast)

Self-hosted app that turns a show's sources into a scheduled, multi-speaker AI
podcast with a public RSS feed. This file is the contract for every story: read
it, then read the GitHub issue, then implement exactly that issue.

## Workflow
- Roadmap = GitHub issues #1–#36 in `faaizzz/Bring-Your-Own-Podcast-BYOP`, tracked on project board 2 (owner `faaizzz`).
- Pick the Todo item with the lowest `Order` (= issue number); every issue under "Depends on" must be closed first.
- Full steps: `docs/IMPLEMENTATION_WORKFLOW.md`. Work **directly on `main`** — no branches, no PRs.
- Implement the issue's scope and nothing more; honour its "Out of scope".
- Done means: every acceptance criterion met, `make check` green, docs updated, commit pushed with `Closes #N`.
- Never weaken or skip tests to get green. Never commit secrets or a real `.env`.

## Stack
- API: Python 3.12, FastAPI, pydantic v2 + pydantic-settings, async SQLAlchemy 2 + asyncpg, Alembic, Celery (+beat) on Redis, structlog, httpx.
- Data: PostgreSQL 16 (with `pg_trgm`), Redis 7. Audio mixing with ffmpeg.
- Web: Vite + React 18 + TypeScript (strict), react-bootstrap/Bootstrap 5, react-router 7, TanStack Query, react-hook-form + zod, Gradient Able admin look.
- Runtime: docker compose (`api`, `worker`, `beat`, `web`, `postgres`, `redis`; optional profiles `minio` (S3-compatible object store, image is RustFS), `kokoro`, `langfuse`).

## Layout
```
apps/api/byop/        FastAPI package
  main.py             app factory
  config.py           pydantic-settings (reads .env)
  db.py               async engine + session dependency
  redis_client.py     shared async Redis client + dependency
  logging.py          structlog JSON logging with request id
  worker.py           Celery app + tasks entrypoint
  api/                routers, ONE FILE PER RESOURCE (shows.py, speakers.py, ...)
  services/           domain logic — never in routers
  pipeline/           the generation run: `orchestrator.py` (stage execution, fail/cancel/reaper), `context.py` (`RunContext`), `stages/` (one module per stage)
  tasks/              Celery tasks (thin: they call services); register new modules in `worker.py` `include`
  storage/            `Storage` interface + `LocalStorage` / `S3Storage`; everything of a show lives under `shows/<id>/`
  models/             SQLAlchemy models
  schemas/            pydantic request/response models
  providers/llm/      LLM provider abstraction
  providers/tts/      TTS provider abstraction
  security/           crypto, auth helpers
apps/api/alembic/     migrations
apps/api/tests/       pytest (mirrors the byop/ tree)
apps/web/src/
  theme/              Gradient Able SCSS/variables/fonts (+ LICENSE-gradient-able); _overrides.scss holds BYOP additions incl. dark mode
  layout/             sidebar, header, breadcrumb, shell
  pages/<area>/       one folder per area (dashboard, shows, episodes, history, costs, settings, auth)
  lib/                api client (api.ts), helpers
docker/               Dockerfiles, nginx.conf
docs/                 user + contributor documentation
.github/              CI workflows, issue templates
```
New directories or modules must follow these names; update this section if the layout changes.

## Python conventions
- Format and lint with `ruff` (line length 100); `mypy --strict` must pass; no untyped defs, no bare `Any` without a comment.
- Everything I/O is `async`; use async SQLAlchemy sessions injected via dependency. No blocking calls in request handlers.
- pydantic v2 models for all request/response and settings; never return ORM objects from routers.
- Money is `Decimal`/`Numeric`, never float. Timestamps are timezone-aware UTC.
- Routers are thin: parse input → call a service → return a schema. Every service query filters by `user_id`.
- Provider keys are read only through `CredentialResolver` (`services/credentials.py`: user override encrypted with Fernet from `BYOP_SECRET_KEY` → `.env` → `ProviderNotConfigured`; enforced by `tests/test_provider_key_access.py`). Providers receive a resolved `ProviderConfig`. API responses mask secrets (`sk-…1234`); `logging.py` redacts secret-looking keys/values. Rotating `BYOP_SECRET_KEY`: `docs/security.md`.
- Structured logging via structlog; no `print`.
- Providers are named by a `ProviderRef` (`services/provider_ref.py`): a built-in name or `conn:<uuid>` of a `ProviderConnection` (`models/connection.py`, `services/connections.py`, `api/connections.py`), stored as text in `Show.llm_provider` / `Speaker.tts_provider` / `fallback_tts_provider`. Resolve one with `CredentialResolver.get_ref(user_id, ref, "llm"|"tts")` (it checks the connection exists, is enabled and has that use) and build the client from `config.provider`: `get_llm(config.provider, config)`. A connection's `ProviderConfig` has `provider=OPENAI_COMPATIBLE` (the enum value now only means "a connection"; there is no `openai_compatible` credential any more), `headers` (secret, never log them) and `label`; usage records carry `conn:<name>`. Pickers use `GET /api/providers?capability=`, never a hard-coded list. A connection in use cannot be deleted or switched off for that use.
- LLM calls only through `byop/providers/llm` (`get_llm(...).complete(..., metadata=CallMetadata(...))`); thin wrapper over the OpenAI SDK, no LangChain. The SDK defaults to httpx2, so providers pass an explicit `httpx` client — keep that, it is what makes `respx` mocks work. Close providers with `aclose()`. Tests block non-loopback network access; mock HTTP with `respx`. See `docs/providers.md`.
- TTS only through `byop/providers/tts` (`get_tts(...).synthesize(..., output_dir=...)`): output is always WAV 24 kHz mono 16-bit in a caller-owned dir. A provider's limits/formats/params live in its `ProviderQuirks` — never branch on the provider name elsewhere. A provider's accepted parameters (name, type, range) are `ParamSpec`s in its `ProviderQuirks`; speaker `voice_params` and previews are validated from them via `voice_param_problems`. Cross-field request errors use `services/validation.py` (`FieldValidationError` → 422 with FastAPI-shaped `loc`/`msg`). A provider's speech models are `TTSProvider.list_models()` (`ProviderQuirks.model_param` names the voice setting that holds the choice, `voices_follow_model` says the voice list depends on it; `GET /api/voices/models`, `GET /api/voices?model=`, cached in `services/voices.py`); the web shows it as `VoiceModelPicker`, and `ParamField.model` in `pages/shows/form/schema.ts` marks that field so it stays out of the voice settings. Kokoro (local, keyless) is the fallback default TTS: `services/defaults.py` picks the first configured paid provider, else Kokoro if its server answers. Use `anyio.Path` for file ops in async code (ruff ASYNC rules).
- Models (`byop/models/`, one module per aggregate; `columns.py` has the id/timestamp/`user_id` helpers): UUID `id`, tz-aware `created_at`/`updated_at`, `user_id` FK on every owned table. Enums are `StrEnum`s in `models/enums.py` stored as VARCHAR + CHECK via `enum_type()` (never free text, never native PG enums). Children of a show cascade at the DB level (`ondelete="CASCADE"` + `passive_deletes=True`); `usage_events` deliberately outlive shows/runs (SET NULL) so cost history survives.
- Migrations: autogenerate, then review by hand (no duplicate enum constraints, working `downgrade`). `tests/test_migrations.py` checks upgrade, no model drift and downgrade to base. Tests recreate the `byop_test` DB from migrations each session. The api container runs `alembic upgrade head` before starting; the admin user is seeded at startup from `BYOP_ADMIN_*` (never overwritten once it exists).

## TypeScript conventions
- `strict: true`; **no `any`** (use `unknown` + narrowing). Prefer `type` imports.
- Server state through TanStack Query only (no ad-hoc fetch in components); API calls go through `src/lib/api.ts`.
- Forms: react-hook-form + zod. Components are function components with explicit prop types.
- Every dropdown is a searchable one: `components/SearchableSelect.tsx` (react-select, styled in `theme/_overrides.scss`, light and dark) or, inside the show form, `pages/shows/form/SelectField.tsx`. Never `Form.Select`, `<select>` or `<datalist>` (`src/noPlainSelect.test.tsx` fails). Options are `{value, label, keywords?, description?, badge?, group?}`; pass `allowCustom` where a typed value is legitimate (model ids, voice ids, time zones, language tags). Tests use `choose`/`chosen` from `src/test/select.ts`. Provider pickers take their options from `useProviderOptions` (`/api/providers`), languages from `lib/languages.ts`.
- Lint with eslint, format with prettier; `npm run check` runs lint + typecheck + vitest + build. Multipart uploads go through `api.post(path, FormData)`. Tests live next to the code as `*.test.ts(x)`; shared test helpers in `src/test/`. Show forms are one react-hook-form + zod model (`pages/shows/form/schema.ts`) shared by the wizard and the Settings tab; it mirrors API rules and maps API 422s onto fields (`applyServerErrors`). Voice settings per provider are listed in `VOICE_PARAMS` there and must stay in step with the providers' `ParamSpec`s. Icons come from `react-icons/fi`; transient messages go through `useToast()` (`lib/toast.ts`, provided by the admin layout); per-resource query hooks live in `lib/<resource>.ts` (e.g. `lib/integrations.ts`); page components are default exports, routes in `src/routes.tsx`, sidebar/breadcrumb menu in `src/layout/menu.ts`.

## Testing expectations
- Every story adds tests for its new behaviour. API: pytest + pytest-asyncio against a real Postgres (transaction rollback per test); external HTTP is mocked with `respx`. Web: vitest + @testing-library/react.
- Do not call real paid APIs in tests. Assert behaviour, not implementation details.
- `make check` = lint + typecheck + tests for every part of the repo that exists. It must pass before each commit.

## Infra notes
`docker/nginx.conf` resolves `api` at request time (Docker resolver + variable `proxy_pass`) so recreating the api container never leaves the web proxy on a stale IP; keep that pattern for any new upstream.

## CI
`.github/workflows/ci.yml` runs on push and PR: `api` (installs ffmpeg, then ruff, mypy, pytest with postgres+redis services), `web` (eslint, tsc, vitest, build on Node 22), `compose` (repo checks + `docker compose build`), `e2e` (push only: Playwright against `docker-compose.e2e.yml` with `tests/e2e/mock_llm`; `make e2e` locally, see `docs/e2e.md`; change the UI's labels and you may need to change `tests/e2e/byop.spec.ts`). Keep it in step with `make check`; GitHub-hosted runners only.

## Commands
`make up|up-full|build|build-full|down|down-v|logs|logs-full|migrate|test|lint|typecheck|check|fmt|e2e|screenshots` (`make help` lists them; `up-kokoro|up-minio|up-langfuse` are aliases of `up-full` for one profile). `make up` is the **minimal** stack (api, worker, beat, web, postgres, redis); `make up-full` adds the compose profiles in `BYOP_PROFILES` (default `kokoro langfuse minio`) and sets `BYOP_BUNDLED_KOKORO_URL` so Kokoro only looks configured when its server is part of the stack (`KOKORO_BASE_URL` is empty otherwise; `default_tts_provider` also probes it with a short timeout); `make down` uses `--profile '*'` so nothing is left running, `make down-v` also deletes volumes. `make up` creates `.env` from `.env.example` and generates `BYOP_SECRET_KEY` if empty; `docker-compose.override.yml` adds dev hot reload. `make test` (and `check`) first starts postgres/redis via compose (`make deps`); tests use the `byop_test` database from `TEST_DATABASE_URL`, created and migrated on demand. `make migrate` applies Alembic migrations. `make screenshots` rebuilds the README pictures in `docs/images/` from the e2e stack (`tests/e2e/screenshots.spec.ts` seeds a demo show; run it whenever the UI changes visibly, then look at every picture: no real keys, header values, emails or personal data). Local stack: `cp .env.example .env && make up`, then web on http://localhost:8080 (API under `/api`).

## Configuration
All configuration comes from environment variables documented in `.env.example` (single source of truth). Collecting stories lives in `services/ingest/` (`canonical`, `dates`, `language`, `extract`, `collect`, `store`, `pipeline`); `python -m byop.cli ingest <show>` runs it inline. Duplicate detection compares a whole batch against the database in one statement (pg_trgm), never in a Python loop. Choosing an episode's stories is `services/ranking.py` (`python -m byop.cli rank <show>` is a dry run). Items a run has picked are held in `items.reserved_run_id` through one `SKIP LOCKED` statement; whoever ends a run must call `release_items` (failed, cancelled, rejected draft) or `commit_items` (episode created). Prompts live as Jinja2 templates in `byop/pipeline/prompts/` (one per show style plus shared `_*.md` partials) and are snapshot-tested; the model is told which language to write in rather than being given per-language templates. Anything that touches audio goes through `services/ffmpeg.py` and works on files (never `bytes` of a whole episode; use `Storage.put_file`/`get_file`); mixing is `services/audio_mix.py`. Stages that do many things at once (like `tts`) must keep all database access in the stage's own task: workers only do I/O and report through a queue (`services/synthesis.py`), because cancelling a task in the middle of a DB write wrecks the session. Reviewing a draft is `services/episodes.py` (+ `api/episodes.py`): a script has a `revision` (bumped by every edit of its lines) and the audio an `audio_revision`; approval requires them equal (`services/script_revision.py` has the helpers and imports nothing, so stages can use it). A re-synthesis is a run with trigger `resynth` that runs only `RESYNTH_STAGES` (`enqueue_run(run_id, names)`); `finalize` publishes when `show.auto_publish` (never for a `resynth` run) else sets the run `awaiting_review`. Streaming audio with `Range` uses `services/byte_ranges.py` + `Storage.get_stream(start=, end=)` (reuse it for the public feed audio). Scratch files of a run live in `MEDIA_ROOT/work/<run id>/` (`pipeline/workdir.py`) and are removed when it ends. A run's stages are plain functions over a `RunContext` in `pipeline/stages/`; they log with `ctx.log`, report with `ctx.progress` (also the heartbeat the reaper relies on) and call `ctx.checkpoint()` between steps. Raise `StageFailed` for a terminal error and `TransientStageError` for a retryable one. The live run view is `GET /api/runs/{id}/stream` (SSE, `services/run_stream.py`): the database is the source of truth, `announce(redis, run_id)` on channel `run:<id>` only wakes open streams (the `RunContext`, the orchestrator and the cancel endpoint call it after committing), and the web `useLiveRun` (`lib/runs.ts`) falls back to polling; nginx has an unbuffered location for the route. The dashboard is one aggregated query set in `services/dashboard.py` served by `GET /api/dashboard` (web: `useDashboard`); keep it a single request. Tracing: `services/langfuse.py` sends each stage's spans and each LLM/TTS call (taken from the same `UsageRecord`s, so no pipeline signature changes) to Langfuse's HTTP ingestion API, once per stage, with a short timeout; it must never fail or noticeably slow a run (`open_tracer` returns a no-op without credentials, and stores `runs.trace_id`). Usage and cost: providers call `record_usage` (`providers/common.py`, one `UsageRecord` per finished call, nothing else) into the active `UsageCollector`; `run_stage` collects per stage and `ctx.log`/`ctx.progress` flush while it works, anything outside a run wraps the work in `capture_usage` (`services/usage.py`) — a new call site of `get_llm`/`get_tts` that bills must run inside one. Cost = provider-reported, else `services/pricing.py` (`byop/pricing.yaml` + the user's `price_overrides`), else `unknown` (stored as 0); run totals are set by `refresh_run_totals` when a run ends. The public podcast feed is `services/podcast_feed.py` (`build_feed`, one element tree, published episodes only, GUID = episode id) served by `api/public.py` (`/feeds/<slug>.xml`, `/media/episodes/<id>.mp3`; outside `/api`, so nginx has a location for them and `tests/api/test_guard.py` lists them as public); absolute URLs always come from `PUBLIC_BASE_URL`, and `api/audio_response.py` is the one place that serves MP3 with `Range`. The history list is `services/history.py` (+ `api/history.py`): keyset cursor on `(created_at, id)`, filters in `HistoryFilters`; the web `RunHistory` component serves the History page and a show's Runs tab. Schedules: `services/schedule.py` (`compute_next_run`, `next_run_for`, `start_due_runs`) and the `byop.schedule_tick` beat task (`tasks/schedule.py`, every 60 s); any change of a schedule field, timezone or `paused` must recompute `shows.next_run_at` (`SCHEDULE_FIELDS` in `services/shows.py`). Long jobs run as Celery tasks that keep their state in Redis (see `services/discovery_jobs.py`); a task creates its own DB engine (NullPool) and Redis client because it runs in its own event loop. Any server-side fetch of a user-supplied URL goes through `services/safe_http.fetch_bytes` (public addresses only; see `docs/sources.md`); tests replace `safe_http.resolve_host` instead of touching DNS. Media goes through `byop/storage` only (`StorageDep`), never `open()` on `MEDIA_ROOT` or boto3 directly; `STORAGE_BACKEND=local|s3` with `S3_*` (see `docs/storage.md`). The model that discovers sources is chosen in `choose_model` (kept pure): the user's Settings choice (`user_settings` table, `services/user_settings.py`; every place that builds a `DiscoveryRequest` fills `discovery_llm_*` from `load_discovery_choice`; `api/user_settings.py`, `GET/PUT/DELETE /api/settings/discovery-model`) > `DISCOVERY_LLM_*` > the show > the default; a connection chosen there counts as in use. Put future per-user defaults in `user_settings`. Whether a model can search the web is `services/web_search.py` (`check_web_search` → yes/no/unknown, OpenRouter from the cached model list); discovery refuses `no` with a 422 before queueing (`precheck_discovery`), warns on `unknown`, and `services/discovery_errors.py` turns a provider's rejection into a plain-language job error (providers keep status/code/detail on `LLMError`, scrubbed of keys). Instance defaults for new shows come from `DEFAULT_LLM_PROVIDER`/`DEFAULT_LLM_MODEL`/`DEFAULT_SHOW_STYLE`. Settings fail fast with a readable `ConfigError` (e.g. missing `BYOP_SECRET_KEY`). Adding or changing a variable means updating `.env.example`, the README/docs and this file together.

## Auth and multi-user
v0.1 is single-user: one admin seeded from `.env` (bcrypt hash in `users`). Login sets a signed JWT (`byop_session`, httpOnly, SameSite=Lax, Secure over https) valid `BYOP_SESSION_HOURS`; its `pv` claim fingerprints the password hash, so changing the password ends old sessions. Login is limited to 5/min per IP (Redis; keyed on the last `X-Forwarded-For` entry added by nginx; fails open if Redis is down).
- **Guard is the default**: in `byop/api/__init__.py` only `health` and `auth.public_router` are public; register every other router on the `protected` router (it depends on `current_user`). `tests/api/test_guard.py` enumerates the OpenAPI routes and fails if one answers an anonymous call with anything but 401 — add a route to its `PUBLIC_ROUTES` only for the RSS feed / episode audio / show covers and the like.
- Routers take `CurrentUser` (from `byop.api.deps`) and pass `user.id` to services, which filter every query by it.
- Web: `useMe`/`useLogin`/`useLogout` in `src/lib/auth.ts`, `RequireAuth` wraps the admin routes, and a 401 from any query clears the session so the guard redirects to `/login`.
- **Multi-user later**: the `users` table and `user_id` on every owned table already exist. Add an invite/signup flow (and per-user settings) that inserts `User` rows; `current_user`, services and tests already scope by `user_id`, so no schema change to owned tables is needed. `is_admin` gates instance-level settings.

## Security and releases
nginx (`docker/nginx.conf`) sets the security headers (strict CSP: the app may only talk to its own origin, so a new external script/font/API host needs a CSP change and an e2e run), the 1 MB body limit (uploads of covers/audio have their own locations) and keeps the Host port (`$http_host`, not `$host`, or API redirects lose the port). The API has no CORS middleware on purpose. Public routes are rate limited per client (`PUBLIC_*_RATE_PER_MINUTE`, login 5/min). Images are published by `.github/workflows/release.yml` on a `v*` tag (`BYOP_VERSION` selects them in compose; see `docs/releasing.md`); dependency audits run in `audit.yml`. Never push a release tag without the user's go-ahead.
